# FE-001: Inventory Management

## Status

`completed`

## Requirements

- Display inventory quantity for each product in the Products list.
- Highlight low-stock products visually.
- Allow filtering products by inventory status (All / In Stock / Low Stock / Out of Stock).
- Existing search, routing, and product detail functionality must be unaffected.

## Acceptance Criteria

- [x] Inventory quantity column is visible in the Products table.
- [x] Low-stock products are clearly identifiable (visual highlight or badge).
- [x] Users can filter products by inventory status.
- [x] Existing product search, status display, and detail navigation continue to work.

---

## Investigation

### Current State

| File | Relevant Finding |
|---|---|
| `src/types/index.ts` | `Product` has no `inventory` field |
| `src/mocks/data.json` | No `inventory` values in any product record |
| `src/services/api.ts` | `getAll()` and `search()` cast to `Product[]` — adding the field propagates automatically |
| `src/features/products/api/useProducts.ts` | Returns full product list; filtering will be done client-side |
| `src/features/products/components/ProductListTable.tsx` | 4-column table: Name, Category, Status, Price |
| `src/pages/ProductsPage.tsx` | Owns search state; passes data down to `ProductListTable` |
| `src/pages/ProductDetailsPage.tsx` | Renders `product.status`, `product.price`, `product.category` — no inventory shown yet |

### Gaps

1. `Product` type missing `inventory: number`.
2. Mock data missing `inventory` values.
3. No filter UI for inventory status.
4. No visual differentiation for low-stock products.

### Inventory Status Thresholds (proposed)

| Status | Condition |
|---|---|
| `out-of-stock` | `inventory === 0` |
| `low-stock` | `inventory >= 1 && inventory <= 5` |
| `in-stock` | `inventory > 5` |

These thresholds will be defined as a single constant in the filter component so they are easy to change.

### Filtering Approach

Client-side. `useProducts` already returns the full list. `ProductsPage` will hold `inventoryFilter` state and derive the filtered array before passing to `ProductListTable`. No new API method needed.

## Implementation Plan

### Step 1 — Extend the data model

**`src/mocks/data.json`** — add `inventory` to each product:

```json
{ "id": "p1", ..., "inventory": 23 }   // in stock
{ "id": "p2", ..., "inventory": 4  }   // low stock
{ "id": "p3", ..., "inventory": 0  }   // out of stock
{ "id": "p4", ..., "inventory": 11 }   // in stock
{ "id": "p5", ..., "inventory": 3  }   // low stock
{ "id": "p6", ..., "inventory": 7  }   // in stock
```

**`src/types/index.ts`** — add field to `Product`:

```ts
inventory: number;
```

### Step 2 — Add inventory filter component

**New file: `src/features/products/components/InventoryFilter.tsx`**

Pill-button group: `All | In Stock | Low Stock | Out of Stock`.

Export `InventoryStatus` type and `LOW_STOCK_THRESHOLD = 5` constant from this file so they can be reused in the table.

Props: `value: InventoryStatus`, `onChange: (v: InventoryStatus) => void`.

### Step 3 — Update `ProductsPage`

**`src/pages/ProductsPage.tsx`**

- Add `inventoryFilter` state (`useState<InventoryStatus>('all')`).
- Derive `filteredProducts` by filtering `products` array against `inventoryFilter` before passing to `ProductListTable`.
- Render `<InventoryFilter>` in the header row alongside `<ProductSearch>`.

### Step 4 — Update `ProductListTable`

**`src/features/products/components/ProductListTable.tsx`**

- Add `Inventory` column header.
- Render `product.inventory` as a number in each row.
- Apply low-stock row highlight (`bg-amber-50`) and an inline badge (`Low Stock` in amber) when `inventory <= LOW_STOCK_THRESHOLD && inventory > 0`.
- Apply out-of-stock styling (`bg-red-50/40`) and badge (`Out of Stock` in red) when `inventory === 0`.
- Import `LOW_STOCK_THRESHOLD` from `InventoryFilter` to keep the threshold DRY.

---

## Dependencies / Blockers

None. All changes are self-contained within the products feature and its data layer.

## Notes

- `api.ts` does not need changes. Its type cast `as Product[]` will include `inventory` once the type and mock data are updated.
- `ProductDetailsPage` is out of scope for FE-001 — the detail page does not need inventory display per the acceptance criteria.
- The `InventoryStatus` type and `LOW_STOCK_THRESHOLD` constant should live in `InventoryFilter.tsx` (not in `types/index.ts`) since they are UI/filter concerns, not data model concerns.
